This guide walks you through finding the CNAME and TXT values you need from Vercel.

<Callout type="warn">
  **Vercel always needs both records.** On is-pinoy.dev, a Vercel domain needs a
  `CNAME` **and** a `vc-domain-verify` `TXT` record — the TXT is not optional.
  See [Why the TXT record is always required](#why-the-txt-record-is-always-required)
  for the reason.
</Callout>

## Prerequisites

- Your portfolio is already deployed on Vercel
- You have chosen a subdomain (e.g. `yourname.is-pinoy.dev`)

---

<Steps>
  <Step>
    ## Open your project's Domain settings

    1. Go to [vercel.com/dashboard](https://vercel.com/dashboard) and sign in
    2. Click on your portfolio project
    3. Click the **Settings** tab
    4. In the left sidebar, click **Domains**
  </Step>
  <Step>
    ## Add your is-pinoy.dev subdomain

    In the domain input field, type your full subdomain:

    ```
    yourname.is-pinoy.dev
    ```

    Click **Add**. Vercel will display a panel showing the DNS records you need to configure.

    <Callout type="warn">
      Do this step first. Vercel only generates your project-specific CNAME
      target and your verification value **after** the domain is added here. If
      you skip this, you have nothing to put in your JSON file — and pointing
      the CNAME at your `*.vercel.app` deployment alias instead will make the
      subdomain 404. The validator warns you if it spots a `*.vercel.app` target.
    </Callout>
  </Step>
  <Step>
    ## Copy your CNAME value

    Vercel will show a **CNAME** record with a value that looks like:

    ```
    xxxxxxxxxxxxxxxx.vercel-dns-017.com.
    ```

    This value is unique to your project. Copy it exactly — you will paste it into your JSON file.

    <Callout type="info">
      Vercel shows the value with a trailing dot (`.`). Keep it — it is the
      standard way to write a fully-qualified name, and it is how every example
      in these docs is written. (The registry strips it before syncing, so a
      value without the dot also works.)
    </Callout>
  </Step>
  <Step>
    ## Copy your TXT verification value

    Vercel also displays a **TXT** record for domain ownership verification:

    ```
    vc-domain-verify=yourname.is-pinoy.dev,abc123
    ```

    Copy the full value, exactly as shown. You need this — Vercel will not
    serve your subdomain until the challenge resolves.

    <Callout type="info">
      Vercel shows this record with a **name** of `_vercel` (or
      `_vercel.is-pinoy.dev`). You do not need to copy the name — only the
      value. The registry knows where the record goes and creates it for you
      from the `"provider": "vercel"` field.
    </Callout>
  </Step>
  <Step>
    ## Create your subdomain JSON file

    Now that you have your DNS values, go to [Create Your JSON File](/guides/workflow/create-file) to add them to your file.

    For reference, here is what your JSON should look like:

    <Tabs items={["CNAME + TXT (required)", "CNAME only (will not verify)"]}>
      <Tab value="CNAME + TXT (required)">
        ```json
        {
          "$schema": "https://raw.githubusercontent.com/is-pinoy-dev/ecosystem/main/packages/schemas/schema/v1/subdomain.schema.json",
          "subdomain": "yourname",
          "owner": {
            "github": "your-github-username"
          },
          "records": {
            "CNAME": {
              "value": "xxxxxxxxxxxxxxxx.vercel-dns-017.com."
            },
            "TXT": {
              "value": "vc-domain-verify=yourname.is-pinoy.dev,abc123",
              "provider": "vercel"
            }
          }
        }
        ```
      </Tab>
      <Tab value="CNAME only (will not verify)">
        A CNAME-only file passes validation, but Vercel will leave your domain
        unverified and answer requests with an error until you add the TXT
        record. Use the other tab.

        ```json
        {
          "$schema": "https://raw.githubusercontent.com/is-pinoy-dev/ecosystem/main/packages/schemas/schema/v1/subdomain.schema.json",
          "subdomain": "yourname",
          "owner": {
            "github": "your-github-username"
          },
          "records": {
            "CNAME": {
              "value": "xxxxxxxxxxxxxxxx.vercel-dns-017.com."
            }
          }
        }
        ```
      </Tab>
    </Tabs>

    Replace `yourname`, `your-github-username`, and the record values with your actual information.
  </Step>
</Steps>

## Why the TXT record is always required

Vercel checks domain ownership at the **registrable domain** boundary, not at
your subdomain. Because `is-pinoy.dev` is not on the
[Public Suffix List](https://publicsuffix.org), that boundary is `is-pinoy.dev`
itself — so Vercel looks for the challenge at `_vercel.is-pinoy.dev`, never at
`_vercel.yourname.is-pinoy.dev`.

That has two consequences worth understanding:

- **You always get a challenge.** Adding a `*.is-pinoy.dev` domain to a Vercel
  project you don't own the apex of always produces a `vc-domain-verify` value.
  There is no "already verified" shortcut.
- **You never create the record yourself.** The registry places your value at
  the shared `_vercel.is-pinoy.dev` name. DNS allows many TXT records at one
  name, so every contributor's challenge coexists there safely, and each is
  matched back to its own subdomain by the target embedded in the value. All
  you supply is the value plus `"provider": "vercel"`.

## Important notes

- **`"provider": "vercel"` is mandatory** — the schema requires `provider` on
  every TXT record, and `vercel` is currently the only accepted value.
  Validation fails with `records.TXT: Invalid input` if you leave it out.
- **Keep the record DNS-only** — do not set `"proxied": true` on a Vercel CNAME.
  Vercel validates certificates by querying DNS directly, and the Cloudflare
  proxy interferes with that. (This is also why the [Site Audit](/tools/site-audit)
  tool, which needs `proxied: true`, is a poor fit for Vercel-hosted sites.)
- **"Invalid Configuration" on Vercel's dashboard** — Vercel shows this warning
  until your PR is merged and DNS has propagated. This is expected. Vercel
  cannot verify the records until they are live.
- **The TXT record is temporary** — Vercel's challenge is single-use. Once your
  domain is verified and serving, the registry detects it and may open a
  cleanup PR removing the TXT entry from your JSON file. This is safe and
  expected: re-verification always issues a fresh value anyway.
