---
title: Common Errors
description: Validation errors from the CLI validator and how to fix each one.
---

These are the messages reported by `npx @is-pinoy-dev/validate` and by CI, and how to fix each one.

Schema problems are printed as `<field path>: <message>`. Registry-level problems (duplicates, filename mismatches, reserved names) are printed as a plain sentence.

## `records.TXT: Invalid input`

**Cause:** your TXT record is missing the required `provider` field, or uses a provider that isn't supported. `vercel` is currently the only accepted value.

**Fix:** add `"provider": "vercel"` to your TXT record:

```json
"TXT": {
  "value": "vc-domain-verify=yourname.is-pinoy.dev,abc123",
  "provider": "vercel"
}
```

---

## `subdomain: Subdomain must be at least 3 characters`

**Fix:** choose a subdomain that is at least 3 characters long. Single- and two-character subdomains are not allowed:

| Invalid | Valid |
|---------|-------|
| `jb` | `jun` |
| `ab` | `abc` |

---

## `subdomain: Invalid string: must match pattern /^[a-z0-9-]+$/`

**Fix:** use only lowercase letters, numbers, and hyphens. No uppercase, no underscores, no dots:

| Invalid | Valid |
|---------|-------|
| `Juan` | `juan` |
| `juan_dev` | `juan-dev` |
| `juan.dev` | `juan-dev` |

<Callout type="warn">
  Leading and trailing hyphens (`-juan`, `juan-`) currently slip past this
  pattern, but they are not valid DNS labels and your PR will be sent back in
  review. Don't use them.
</Callout>

---

## `owner.github: Invalid input`

**Cause:** the `owner.github` field is missing or is not a string.

**Fix:** add it, matching your GitHub username exactly (case-sensitive):

```json
"owner": {
  "github": "JuanDeLaCruz"
}
```

---

## `Reserved subdomain: <name>`

**Fix:** choose a different name. Certain subdomains are reserved for platform use (e.g. `api`, `status`, `mail`, `admin`, `_tools`). See the full list in [Naming Rules](/guides/getting-started/naming-rules#reserved-names).

---

## `Filename mismatch: juan.json vs juan-dev.json`

**Cause:** the `subdomain` field and the filename disagree. This check runs in CI, across the whole `subdomains/` directory.

**Fix:** make them identical — either rename the file or update the field:

```json
{
  "subdomain": "juan-dev"
}
```

```bash
mv subdomains/juan.json subdomains/juan-dev.json
```

---

## `Duplicate subdomain: <name>`

**Cause:** two files in `subdomains/` declare the same `subdomain` value. Usually this means the name is already claimed.

**Fix:** pick a different subdomain. If you believe the existing file is yours, say so in your PR.

---

## Warning: CNAME points at a `*.vercel.app` alias

This is a **warning**, not an error — validation still passes, but your subdomain will almost certainly 404.

```text
⚠ juan: CNAME target "juan.vercel.app" looks like a Vercel deployment alias
  (*.vercel.app), not the vercel-dns-*.com target Vercel issues for a custom
  domain — confirm this domain has been added in the Vercel project's
  dashboard, or it will 404
```

**Fix:** add `yourname.is-pinoy.dev` as a custom domain in your Vercel project first, then use the `*.vercel-dns-*.com` target Vercel gives you. See the [Vercel guide](/guides/providers/vercel).

---

## Rules the validator does not enforce

These will still get your PR sent back, so check them yourself:

- **`A` and `CNAME` together.** A name can be an alias (CNAME) or a direct address (A), not both. Use one.
- **Leading or trailing hyphens** in the subdomain.
- **`owner.github` must match the account opening the PR.**
- **The subdomain must point at something real and live.**
- **Trailing dot on CNAME values** is a convention we follow in every example, not a validation rule — values with and without it both pass, and the registry normalizes them.
