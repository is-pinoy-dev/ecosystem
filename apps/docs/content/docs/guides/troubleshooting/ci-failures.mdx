---
title: CI Failures
description: How to fix CI failures on your subdomain registration pull request.
---

When you open a PR, a GitHub Action validates every file in `subdomains/` and posts the result as a comment. On later pushes it edits that same comment instead of adding a new one.

## Reading the comment

A failure looks like this:

> ## ❌ Subdomain Validation Failed
>
> The following errors were found:
>
> ```
> ✖ subdomain: Subdomain must be at least 3 characters
> ```
>
> Please fix the errors above and push again.

Each `✖` line is one problem. See [Common Errors](/guides/troubleshooting/common-errors) for what each message means.

A pass looks like this:

> ## ✅ Subdomain Validation Passed
>
> All subdomain files are valid.

## Warnings

A passing run can still include a **⚠️ Warnings** section. Warnings do not block your PR, but they usually mean the subdomain will not work once it goes live — most often a CNAME pointing at a `*.vercel.app` deployment alias instead of the `*.vercel-dns-*.com` target Vercel issues for a custom domain. Read them and fix the cause.

## Sync dry-run

When the run passes, the comment may also include a **🔍 Sync Dry-Run** section showing exactly which DNS records your PR would create, update, or delete:

```text
  + CREATE  yourname.is-pinoy.dev → xxxxxxxxxxxxxxxx.vercel-dns-017.com.
  + CREATE  _vercel.is-pinoy.dev → vc-domain-verify=yourname.is-pinoy.dev,abc123
```

This is a preview only — nothing is applied until a maintainer merges. It is worth checking: if the records shown are not what you expect, your JSON is not saying what you think it says.

<Callout type="info">
  On a pull request the dry-run is scoped to the subdomain files your PR actually changed, so you will never see entries for other people's subdomains.
</Callout>

## `owner.github` mismatch

`owner.github` must match the GitHub account that opened the pull request, and the check is **case-sensitive**. This one is enforced in review rather than by the validator, so a green CI run does not mean it is correct.

Copy your username from your GitHub profile URL (`github.com/your-username`) and use it verbatim:

```json
"owner": {
  "github": "JuanDeLaCruz"
}
```

## How to push a fix

After editing your JSON file:

```bash
git add subdomains/yourname.json
git commit -m "Fix validation error"
git push
```

This pushes to the same branch you used when opening the PR. CI re-runs automatically within a few seconds, and the existing comment updates in place.
